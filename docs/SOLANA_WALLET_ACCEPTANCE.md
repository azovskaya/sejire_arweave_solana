# Solana: реальная проверка кошелька на другом Mac

Статус шаблона: **NOT RUN** для настоящих Phantom/Solflare. Автоматический программный подписант не меняет этот статус. Следовать `AGENTS.md` и `CONTINUE_ON_ANOTHER_MAC.md`.

## Безопасный запуск

Ветка — `feat/solana-preservation`. Сначала проверить `git status --short --branch`; не стирать правки и не делать reset/force-push. Чистую локальную ветку обновлять только fast-forward. Node 22.12+ или совместимый более новый. В корне проекта:

```sh
npm ci --prefix apps/web
npm ci --prefix apps/sponsor
npm run solana:check
npm run solana:dev
```

Открыть `http://127.0.0.1:5173/` на этом же Mac в **Chrome с установленным кошельком**. Сервер оставить работающим. Если порт занят, не убивать неизвестный процесс. Для другого свободного порта можно использовать `npm run solana:dev -- --port 5176` и открыть фактически напечатанный адрес.

Только синтетические люди и тестовая сеть. Операции подключения/подписи подтверждает владелец. Слова кошелька нигде не вводить и не передавать агенту. Слова SEJIRE — отдельный секрет: владелец хранит их вне Git/отчёта. В первых прогонах разрешение на пополнение **выключено**. Не переключаться на mainnet при ошибке devnet.

## Заполнить среду

- Дата/время и проверенный commit: NOT RUN.
- Версия macOS / Chrome: NOT RUN.
- Кошелёк и версия расширения: NOT RUN.
- Сеть в интерфейсе приложения и кошельке: должна быть devnet, NOT RUN.
- Публичный адрес тестового аккаунта (без секретов): NOT RUN.
- Чистый профиль/origin для восстановления: NOT RUN.

Если установлен только один кошелёк, проверять его; второй отметить NOT RUN. Не устанавливать расширения без отдельного согласия. Статусы ниже менять на PASS/FAIL/BLOCKED только с фактическим результатом.

## Платный devnet-путь — только отдельно с владельцем

Статус: **NOT RUN**. Бесплатный успешный прогон не доказывает оплату SOL.

1. Получить отдельное согласие владельца на показанную максимальную сумму хранения и комиссию. Нужны только тестовые SOL, не покупка реальных средств. Не обходить ограничения faucet и не исчерпывать бесплатную квоту загрузками ради теста.
2. При естественном недостатке бесплатного лимита/кредитов явно включить согласие. Проверить адрес получателя, отправителя, devnet и сумму в расширении. Владелец отклоняет перевод один раз — повтор не должен утверждать, что оплата состоялась.
3. В отдельной разрешённой попытке владелец подписывает перевод. Записать только публичную подпись транзакции и ссылку `https://explorer.solana.com/tx/<signature>?cluster=devnet`, фактическую сумму/комиссию и изменение кредитов Turbo.
4. Контролируемый обрыв ответа сервиса тестировать только после объяснения владельцу риска неопределённого состояния. Сохранить журнал, перезагрузить приложение, возобновить прежнюю попытку. Проверить сверку **той же** подписи, без нового перевода и без ручного пополнения.
5. Если подписанная транзакция не была отправлена либо результат неизвестен, отметить BLOCKED и сверить состояние. Не считать отсутствие ответа доказательством отсутствия платежа. Не очищать IndexedDB и не создавать заменяющий перевод автоматически.

Лимит 0.01 SOL относится к пополнению хранения, не к комиссии сети. Если бесплатный путь не позволяет естественно вызвать оплату, оставить раздел NOT RUN.

## Известные дополнительные проверки UI

- На 390 px после «Вместить» левая карточка частично обрезана: минимальный масштаб 0.55. Пока не исправлено; это не потеря данных.
- При импорте файла слов после архива подсказка «Открыть» не совпадает с кнопкой «Восстановить архив». Восстановление прошло.
- Проверить вручную обратный импорт экспортированного JSON: подтверждение замены существующего **тестового** черновика и отмену. Встроенное браузерное управление зависло на этом шаге; дефект самого импортера не установлен.
- Аудит зависимостей содержит high-находки. Passing tests не заменяют проверку безопасности перед mainnet.

Обновить этот документ и handoff, приложив только безопасные публичные доказательства. Не прикладывать мнемонику, приватные ключи, профиль Chrome, cookies, `.env.local` или настоящие семейные данные. Не отправлять заявку, не развёртывать и не сливать в `main` в рамках этой проверки.
