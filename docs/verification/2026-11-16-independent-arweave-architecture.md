# Независимый SEJIRE: прямое сохранение в Arweave

Дата: 16 ноября 2026. Ветка реализации: `feat/decentralized-arweave-20261116`.

## Цель и граница этого изменения

Новый профиль приложения сохраняет зашифрованный архив непосредственно из браузера
в Arweave. Владелец подтверждает стоимость в своём AR-кошельке; приложение не
требует сервер SEJIRE, Cloudflare Worker, кассу проекта, перевод SOL, конвертацию
SOL → AR или Turbo для сохранения семейного архива. Чтение опубликованного архива
и локальная расшифровка также не требуют оплаты или работающего сервера проекта.

Это изменение архитектуры будущих сохранений. Оно не доказывает получение байтов
ранее оплаченного архива и не удаляет старый журнал обязательств. Копия всех
предыдущих локальных исправлений сохранена в ветке
`checkpoint/ario-repair-before-decentralization-20261116`, commit
`f7be2f6d5ff9a2c106d9d188750efbd83aaa8e62`.

Solana System Program переносит lamports; стандартный transfer сам по себе не
исполняет Arweave upload. Если позже понадобится оплата хранения в SOL при полном
отказе от исполнителя проекта, потребуется отдельный протокол с источником AR,
исполнителями, проверяемым подтверждением хранения, правилами возврата/спора и
независимой проверкой реализации. Перенос HTTP-сервера с Cloudflare на другой
хостинг эту задачу не решает.

## Новый профиль сборки

`npm run arns:build` и `npm run web:build:arns` теперь создают профиль
`decentralized-direct-arweave`. `VITE_DECENTRALIZED_MODE=true` выбирает отдельные
app/publish entrypoints; legacy Fund/Checkout/Sponsor URL явно очищаются при сборке.
`npm run arns:build:funded` и `npm run arns:verify:funded` сохраняют прежний профиль
для проверки старого кода и обязательств.

Сборщик использует обычный Vite config и фиксирует все реально включённые модули
во всех chunks, включая ленивые. Список модулей фиксируется внутри bundler, а
SHA-256 берётся из окончательных файлов после завершения всех Vite hooks.
`bundle-boundary.json` содержит SHA-256 каждого JS chunk, его зависимости и список
включённых модулей. `release-profile.json`
указывает прямое финансирование AR владельцем и отсутствие обязательной услуги
SEJIRE/Solana/bundler. Проверка отклоняет:

- включённые Checkout/Fund/Sponsor клиенты и пакеты Solana/Turbo/Cloudflare;
- Worker/payment API URL и маршруты старого исполнителя внутри JS;
- неописанный или изменённый chunk, внешнюю JS-зависимость и test-only signer;
- старый `admin-lock.json` в новом профиле;
- отсутствие автономного recovery набора или переносимого entry/fallback.

Статическая проверка не заменяет browser-тесты. Новый CI проверяет приложение
на статическом origin с подставными сетевыми ответами и отдельно сохраняет
`permaweb-static-release` именно из независимой сборки. Старые funded/native
проверки продолжают выполняться для совместимости ранее оплаченных операций.

## Публикация сайта отделена от исполнения приложения

`permaweb.yml` принимает только ручной запуск с ветки
`feat/decentralized-arweave-20261116`. По умолчанию выполняется `prepare`:
проверяется полный успешный CI для точных SHA/run/attempt и текущего HEAD,
скачивается соответствующий artifact, сверяется GitHub ZIP digest и каждый файл.
Пакет не пересобирается при выпуске. В provenance включён профиль сборки.

Отдельный режим `upload` остаётся только явно запрошенной операцией публикации
статического сайта. Используемый в этом необязательном пути Turbo SDK не входит
в исполняемое приложение и не требуется владельцам семейных архивов. Сохраняются
ограничения: существующие собственные credits, никакого automatic top-up,
свежая оценка стоимости, один upload attempt GitHub, выключенные повторные подписи
SDK, остановка очереди при первой ошибке, сохранение известного результата перед
публичной проверкой байтов. Оценка не является жёстким лимитом провайдера;
неизвестный ответ не является доказательством отсутствия расхода.

ArNS Target не меняется автоматически. До просмотра пакета, отдельного согласия
владельца на реальную стоимость публикации и проверки размещённых байтов новый
сайт не объявляется опубликованным. Один раз загруженный точный manifest можно
проверять по ID без повторного upload. Worker deploy в новый путь не входит.

## Старый оплаченный архив нельзя потерять при смене архитектуры

Для `AtwLYx509C9jWIFKUNg7dy1GSgiaDbXVK1YEQbBWfHY` прежняя проверка показывала
подтверждённый заголовок, размер 25 269 bytes и недоступные raw bytes. Смена сайта
или отключение сервера не восстанавливают эти байты автоматически.

До завершения этого обязательства нельзя удалять прежний Durable Object,
payload, browser journal, signed transaction или receipt. Если точный ciphertext
сохранился, его chunks можно дослать к тому же transaction ID/data root без новой
оплаты или подписи; это должно быть отдельно проверено для существующего заказа.
Состояние его реального ledger/payload не установлено чтением публичной сети.
Новая ветка не создаёт заменяющий заказ и не тратит дополнительные средства.

## Долговечность и предел обещания «200 лет»

Независимость от компании достигается форматом и копиями: зашифрованный envelope,
точный digest/размер, transaction ID, receipt, спецификация и автономный decoder
должны быть доступны владельцу отдельно от сайта. Recovery words хранятся отдельно
и не входят в публичный пакет. Кошелёк AR нужен для новой записи, но не для чтения
уже сохранённого envelope.

Ссылки на медиа сохраняются как ссылки: `MediaRef.tx` указывает на отдельный
Arweave объект, а `tamgaUrl` может указывать на внешний HTTPS-ресурс. Это не означает,
что байты каждого вложения входят в зашифрованный envelope или recovery kit.
Для долгого хранения такие объекты нужно отдельно сохранить и проверить. Текущий
интерфейс не загружает медиа; эта граница не мешает восстановлению записанного
дерева, но не позволяет обещать сохранность всех внешних изображений.

ArNS — изменяемое удобное имя; immutable transaction/manifest ID остаётся основным
независимым указателем. Публичные gateways заменяемы, однако доступность данных и
поиск по одной фразе всё равно зависят от существования источников/индексов. Известный
ID и локальная копия ciphertext уменьшают эту зависимость. Нельзя гарантировать
наличие сети, шлюзов, DNS, текущего браузера, алгоритмов или ключа через 200 лет.
Arweave использует экономическую модель долговременного хранения, а не гарантию
SEJIRE, что любые будущие операции будут исполняться без поддержки и обновлений.

## Проверки на этом этапе

- Release/профиль regressions на Node 22.23.4: `npm run test:permaweb-prepare`
  — PASS, 20 tests плюс deterministic preparation selftest. Включена регрессия
  изменения кода поздним Vite hook: map модулей сохраняется, digest соответствует
  окончательным байтам.
- Существующие Worker release guards: `node --test scripts/worker-release-gate.test.mjs`
  — PASS, 53 tests; разрешённая ветка Worker по умолчанию не изменена.
- Итоговая локальная independent сборка Node 22.23.4, включая historical reader
  и local completion finalizer, прошла: 10 JS chunks, 337 включённых модулей,
  8 recovery files, без запрещённых runtime модулей/endpoint. TypeScript build
  прошёл; lint не обнаружил новых ошибок. Полный CI и браузерная приёмка
  выполняются после push для окончательного SHA; этот документ не заявляет
  их успех заранее.
- Direct-Arweave core: PASS, 17 сценариев на Node 22.23.4 с настоящей
  криптографией синтетического ключа и подменённым HTTP. Проверены точный replay,
  один/несколько chunks, потерянный ACK, поздняя подпись, перенос подписанной
  операции и отсутствие новой оплаты при продолжении.
- Historical native reader: PASS, 14 сценариев; проверяются подпись/ID, Merkle
  root, точные bytes, metadata и расшифровка. Совместимость прежних тегов не
  ослабляет новый signing contract; ANS-104 item не считается native transaction.
- Independent backup/finalization: PASS, 12 проверок. Восстановленный полный
  offline vault не заменяется старой сетью; completion из History и после reload
  обновляет подходящий HEAD, не перезаписывает другой vault, более новый HEAD
  или явно выбранный файл. Следующее сохранение другого дерева сохраняет
  предыдущие изменения и историю. Отмена сетевой записи подготовленной копии
  сохраняет её полный локальный снимок и прежний network parent для следующего дерева.
- Standalone recovery core/CLI: PASS, 12 tests на Node 22.23.4; interop с текущей
  production crypto/envelope реализацией — PASS. HTML воспроизводится из того же
  decoder и имеет CSP, запрещающий сетевые соединения. Реальный browser-тест
  локально заблокирован `EPERM socket()`; проверка включена в CI, пропуск не
  считается успешной browser-приёмкой.
- Реальная загрузка архива/сайта, wallet approval, Solana payment, Worker deploy
  и смена ArNS Target в рамках этой записи не выполнялись.
