# Sejire: подготовка пилотного выпуска — 16.11.2026

Владелец разрешил внести изменения и проверить итоговый выпуск. Работа продолжает пакет `cursor/ario-permaweb-release-5150` (`3e674ea0a8f09e59bd8c068c79e55e840011628c`); прежние рабочие папки и незакоммиченные правки сохранены. Ветка выпуска — `feat/promo-funded-preservation`; история не переписывается, `main` не используется для этой публикации.

## Изменения

- Сохранён объединённый пакет 15 ноября: отдельная передача всех Arweave chunks, включая маленькие архивы; продолжение прежнего paid-заказа; проверенный запасной путь чтения; актуальный снимок редактора перед сохранением/экспортом; безопасный undo; статическая ArNS-сборка с адресом действующего Worker.
- При неуспешной досылке уже подписанного чанка сервер сохраняет безопасную причину `storage_data_replay_unavailable`. Последующая недоступность шлюза её больше не затирает. Ошибка целостности имеет приоритет, проверенное завершение очищает ошибку. Ответ провайдера и содержимое архива в диагностику не попадают.
- Если чтение сохранённого payload прерывается после захвата lease, сервер освобождает именно этот lease, записывает `paid_payload_missing` или `paid_payload_unavailable` и использует существующий backoff. Оплата, резерв и прежняя подпись сохраняются.
- В полный CI добавлена проверка готового статического клиента для ArNS и его промо-сценариев с имитацией сети. Проверяется встроенный адрес Worker, а не только исходный код.
- README различает исторический успешный Devnet-пример и текущую приёмку Mainnet.

Гипотеза постоянного исчерпания общего таймаута перед досылкой не подтвердилась: операция DirectArweave уже имеет собственный предел. Таймауты не изменялись.

## Зависимости и проверка совместимости

Обновлены `node-forge` 1.4.0 → 1.4.3, DOMPurify 3.4.16 → 3.4.18 и `follow-redirects` 1.16.0 → 1.16.3. Turbo 2.1.0 и Solana web3 1.99.0 сохранены.

Для транзитивного `bigint-buffer` 1.1.5 нет исправленного upstream-релиза. Применён точный npm override `@vekexasia/bigint-buffer2@1.1.1` после проверки четырёх используемых SPL-функций и соответствующего опубликованному пакету исходника. Browser entry использует JavaScript; Node entry содержит Rust binaries, поэтому пакет не объявляется полностью JavaScript. Старый уязвимый C-binding удалён из дерева зависимостей.

В существующий `boundaries.selftest.ts` добавлены 98 проверок фактически разрешаемого SPL converter: u64/u128/u192/u256, оба порядка байтов, независимое сравнение байтов, сохранность соседних sentinel bytes, native/browser fallback, нулевые и невыровненные размеры до 257 байт, число шире выхода и некорректные аргументы. Все 98 и прежние сценарии этого файла прошли без внешних запросов.

Свежий production audit `--omit=dev --audit-level=high`: **web exit 0, 0 critical / 0 high / 10 moderate / 13 low**; sponsor без изменений — **0 critical / 0 high / 1 moderate / 13 low**. Оставшиеся замечания не объявляются устранёнными. Аудит, порог выпуска и runtime-зависимости не скрывались и не переносились в devDependencies.

Первичные источники: [upstream advisory](https://github.com/advisories/GHSA-3gc7-fjrx-p6mg), [release-matched Rust conversion core](https://github.com/vekexasia/bigint-swissknife/blob/7ff9fef3a89edd229259bdb946341b7d12996cff/packages/bigint-buffer2/rust/core/src/lib.rs), [npm package metadata](https://registry.npmjs.org/@vekexasia%2fbigint-buffer2/1.1.1).

Это подтверждает наличие заголовка и недоступность архивных байтов на проверенных маршрутах; не доказывает безвозвратную утрату. Код сохраняет ciphertext, подготовку и подписанный план в `paid_payloads`. Наличие этих строк у конкретного production-заказа не прочитано: нужен существующий авторизованный доступ. Содержимое таблицы нельзя выводить в логи или публиковать.

После выпуска нужно проверить автоматическое продолжение либо использовать существующее явное продолжение **того же заказа**. Новый заказ, повторная SOL-оплата, новая подпись архива и ввод recovery words в чат для этого не нужны.

## Выпуск и приёмка

1. Дождаться полного успешного `SEJIRE checks` для текущего SHA `feat/promo-funded-preservation`, событие `push` или `workflow_dispatch`.
2. Запустить существующий ручной Worker workflow с `confirm=DEPLOY`, точными `ci_run_id` и `ci_attempt`. Перед deploy gate повторно проверяет SHA/ветку/попытку/все шаги; production audit блокирует high/critical. Защиты не ослаблены.
3. Проверить прежний архив: доступные 25269 байт, совпавший SHA-256 из подписанных тегов и восстановление исходного дерева по словам в чистом браузере владельца.
4. Выпустить корневой Pages из принятого CI-артефакта через `pages.yml`: `checked_run=<тот же CI>`, `publish_root=true`; проверить публичный provenance и готовый сайт.
5. Загружать ArNS-пакет и менять Target имени `sejire` только после этой приёмки, используя существующий доступ подписанта. Незавершённый browser journal с github.io автоматически на ar.io не переносится.

Успешный CI, доступность API policy и Arweave transaction ID по отдельности не являются завершённой Mainnet-приёмкой. До фактической проверки байтов и восстановления прежнего архива публичный платный пилот остаётся неподтверждённым.
