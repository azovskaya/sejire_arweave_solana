## Что меняется для владельца архива

Бесплатное скачивание зашифрованной копии доступно без кошелька. Неподписанную
подготовку можно оставить локальной: ciphertext и история остаются, а новая
версия не требует сначала оплатить старую подготовку.

Для новой записи владелец получает цену в AR и отдельно подтверждает подпись в
совместимом Arweave-кошельке. Intent сохраняется до вызова кошелька; полученная
подписанная native-транзакция сохраняется до отправки. Продолжение использует
тот же ID и те же байты, передаёт заголовок и все chunks, включая короткий архив.
Неопределённый ответ кошелька не разрешает новую автоматическую подпись.
Подписанную операцию можно экспортировать; её импорт сам не начинает загрузку.

Завершение требует подтверждённого заголовка и скачанных обратно байтов с точными
размером и SHA-256. Read-only проверка не отправляет данные. Явное продолжение
при подтверждённом заголовке и недоступном файле может дослать chunks прежней
транзакции. Историческое успешное чтение не выдаётся за текущую доступность.

Новый AR-платёж не заменяет прежнюю SOL-оплату и не считается восстановлением
старого заказа. Проверка прежних журналов ограничена доступным browser origin:
новый адрес сайта не получает автоматически данные другого origin. Прежний
браузер, encrypted payload, signed transaction и receipt сохраняются.

Независимый build проверяет все JS chunks, включая ленивые: runtime не должен
содержать Worker/payment endpoints, Checkout/Fund/Sponsor, Solana/Turbo/Cloudflare
модули или тестовый signer. `release-profile.json` и `bundle-boundary.json`
связывают профиль и окончательные файлы. Старые funded-тесты остаются в CI ради
совместимости прежних операций. [Архитектура и границы](2026-11-16-independent-arweave-architecture.md).

Открытый формат и независимые копии уменьшают зависимость от сайта и компании.
Они не гарантируют существование сети, браузера или безопасность нынешней
криптографии через 200 лет. [Инструкция decoder](../../tools/recovery/README.md).

`prepare` не читает wallet key, не подписывает и не загружает. Он проверяет
SHA/run/attempt, ZIP digest и manifest точного CI artifact, сохраняет provenance
и запрашивает публичную оценку. При нулевом пороге возможно `withinBudget: false`;
это оценка, не разрешение расходов и не жёсткий лимит провайдера.

Для текущего выпуска взять выданный `sejire-independent-4d22e9e.zip` и сверить
его SHA-256 с таблицей выше. Он включает точный CI pack и provenance, без
пересборки исходников. Для локальной проверки распаковать именно его содержимое
в `.cache/permaweb-accepted/` checkout принятого source SHA. Если отложенный
GitHub prepare завершится позже, его artifact требует отдельной сверки; не
подставлять его ZIP digest вместо digest выданного пакета.
Корень: `index.html`, `404.html`, `assets/`, `recovery/`, `release-profile.json`,
`bundle-boundary.json`, `release-manifest.json`, `build-provenance.json`.
`admin-lock.json` запрещён. Не подменять пакет старым native/funded artifact
или локальной пересборкой.

Read-only команды из корня checkout:

```sh
npm run permaweb:plan
# После отдельной загрузки владельцем и получения фактического manifest ID:
npm run permaweb:verify -- --manifest MANIFEST_ID
# После отдельного изменения Target владельцем:
npm run permaweb:verify-target -- --manifest MANIFEST_ID
```

Проверки не выполняют upload и не подписывают новую транзакцию. PASS означает
совпадение публичных байтов и fallback сейчас, а не финальный L1 settlement или
доказательство текущей записи владельца имени. Target отдельно сверяется в
управлении именем. Ошибка чтения не является причиной повторить upload.

Публикация сайта — отдельная операция после просмотра пакета, цены и выбранного
кошелька. Необязательный release-time Turbo transport не входит в runtime
семейных архивов. Гарантии retry/abort нашего runner нельзя переносить на другой
uploader или Console. Привязку имени при upload оставить выключенной до проверки
публичных файлов и fallback. Для folder/deploy публикации распаковать ZIP и
загрузить содержимое его корня, выбрать `index.html` как index и `404.html` как
fallback. Успешное размещение одного ZIP как файла не публикует приложение.
Сохранить полученный manifest ID; не загружать пакет повторно из-за временного
отсутствия байтов, сначала проверить уже известный ID.

Перед сменой имени записать прежний Target. Официальный путь в Console:
`console.ar.io/domains/sejire` → Records → карандаш строки `@` → Target =
проверенный `MANIFEST_ID`. Право менять имя определяется owner/controller,
а не просто наличием AR-кошелька для загрузки. Текущая документация Console
описывает отдельную подпись и стоимость изменения через SOL network fee либо
credits; проверить её перед подтверждением. Это управление именем, не обязательная
SOL-оплата семейных архивов. Покупку, transfer, reassign, release и изменение прав
в рамках cutover не выполнять. Источники: [Console: записи и стоимость](https://docs.ar.io/build/guides/working-with-arns/buy-manage-arns-console),
[официальный ArNS UI](https://docs.ar.io/build/guides/working-with-arns/manage-arns-ui/).

1. Принять выданный точный ZIP, provenance и оценку. Перед публикацией получить
   свежую цену: сохранённая оценка не является разрешением расходов и действует
   как предварительный снимок, а upload gate требует цену не старше 60 секунд.
   После отдельной публикации проверить публичный сайт на desktop/mobile;
   синтетический wallet из CI не доказывает работу настоящего расширения.
2. На небольшой синтетической семье проверить настоящее Arweave-расширение:
   цену, выбранный адрес и явное подтверждение владельцем. Зафиксировать публичный
   transaction ID и подписанный reward, не записывая секреты.
3. Получить подтверждение транзакции, скачать фактический ciphertext обратно,
   сверить длину/SHA-256 и восстановить все деревья, связи и историю. Незавершённую
   операцию продолжать с тем же ID, без нового автоматического платежа/подписи.
4. Скачать encrypted backup, данные транзакции и автономный decoder. В чистом
   контексте без сети восстановить файл словами SEJIRE и подтвердить полноту
   данных. Слова вводит только владелец, отдельно от платёжного кошелька.
5. Отдельно закончить прежнее обязательство `Atw…`. До подтверждённой выдачи его
   байтов не объявлять старый архив восстановленным и не удалять исходный контекст.
