# SEJIRE: переход на Arweave-only — 27 ноября 2026

## Решение владельца и границы этого изменения

Владелец потребовал работу протокола только через Arweave без обязательного
централизованного сервиса. Кандидат находится в
`feat/arweave-only-protocol-20261127` и основан на сохранённом funded source
`ef0252025c32687dce018368ea94d74af2728c66`. Main и принятый прежний source не
заменяются автоматически. Исторические журналы, подписанные операции, ciphertext
и оплаченные обязательства остаются совместимыми и не удаляются.

Этот отчёт описывает код и локальную проверку до заморозки кандидата.
**Окончательные remote source SHA, полный exact-source CI/attempt и хеш
принятого ZIP фиксируются отдельным evidence после CI.** Успех прежнего funded
CI не является проверкой новой версии. Здесь не заявляются реальная новая
публикация, списание средств, смена ArNS или приёмка кошельком владельца.

## Что изменено

| Область | Действующее поведение |
| --- | --- |
| Обычный dev/build | Выбирает `decentralized-direct-arweave`; старая серверная конфигурация не включается случайными `VITE_*` из прежней среды |
| Редактор и история | Работают локально; прежний AO mirror использует локальный процесс, а не сетевой hosted executor |
| Новая запись архива | Native Arweave format-2 transaction, подписанная Arweave-кошельком пользователя; фактические AR storage fees |
| Поиск восстановления | Кандидаты из native Arweave GraphQL на заменяемых узлах; пользовательский узел исключает скрытый fallback на публичные индексы |
| Принятие сетевого архива | Проверки подписи, transaction ID, Merkle root, metadata, ciphertext bytes и расшифрованного полного vault; индекс не считается источником истины |
| Восстановление без индекса | Известный native transaction ID или локальный encrypted kit; decoder входит в выпуск и работает без сети |
| Промокод и админка | Новый профиль не обещает серверный промокод, общий секрет казны или парольный сервер; `#/protocol` и прежние admin routes объясняют текущую модель |
| Публикация сайта | Native AR CLI на постоянном диске владельца, без Turbo account/bundler и без временного signer в Actions |
| ArNS | Отдельное изменение уже принадлежащего владельцу имени; прямой manifest ID сохраняется независимо от имени |
| Совместимость | Старые funded/SOL реализации и тесты запускаются явно, их модулей нет в текущем статическом runtime |

Сборка проверяет все действительно включённые модули и все emitted JS chunks.
Граница запрещает SEJIRE API, Cloudflare transport, hosted AO client, Goldsky,
Solana checkout/RPC, Turbo upload/payment SDK, server admin и секреты казны.
Локальные функции истории и совместимые тексты не выдаются за сетевой AO.

## Данные и ограничения

Форматы `sejire/envelope/v1` и `sejire/v0.3` не изменены. Новое сохранение
содержит зашифрованный полный vault, его деревья и историю. Шифрование и
расшифровка происходят в браузере. Архивные слова SEJIRE отличаются от seed
кошелька. Внешние media URL не становятся встроенными media bytes.

Native архив ограничен 10 MiB. Индексы могут отставать и не доказывают полноту
найденной истории; поиск ограничен числом кандидатов, параллелизмом и сроком
ожидания. Известный ID и автономная копия не зависят от доступности индекса.
Ответ узла о числе подтверждений остаётся утверждением узла, а не локальным
light-client доказательством консенсуса. Криптография и реальные полученные
байты проверяются отдельно.

Общий публичный промокод не превращён в размещённый в JS ключ казны. Автоматическое
спонсирование native AR в этой версии отсутствует: вместо прежних 0.03 SOL или
серверного промокода пользователь подтверждает собственную native AR fee.
Это намеренное изменение модели оплаты, а не незаметная имитация старой функции.

ArNS в актуальной документации имеет Solana registry/ANT, поэтому обещание
«только Arweave» относится к самому приложению и архивам, а имя `sejire.ar.io`
является отдельным удобным слоем адресации. См. [официальное описание ArNS](https://docs.ar.io/learn/arns)
и [инструкцию Console](https://docs.ar.io/build/guides/working-with-arns/buy-manage-arns-console).

## Защита публикации сайта

Новые подписи привязаны к реальному ZIP успешного CI, его digest/размеру,
source SHA/attempt, проверенному manifest и точным файлам. Локальный
`build-provenance.json` не заменяет эту проверку: ZIP повторно скачивается,
безопасно распаковывается и сравнивается с локальным release.

Постоянный местный журнал блокируется одним процессом. Намерение подписи
сохраняется до вызова signer, подписанные байты — до первого POST; записи
синхронизируются с диском. Неизвестный результат подписи блокирует новую
подпись. Лимит fees считается целыми winston и включает уже подписанные
операции и неизвестные намерения. Автоматического пополнения нет.

Явный `replay` повторяет только прежние подписи, заголовки и все chunks,
не требует приватного ключа и не зависит от текущего HEAD GitHub. `resume`
может подписывать оставшиеся файлы и потому снова проверяет CI ZIP и лимит.
ACK не заменяет хранение: если ответ был принят, но данные не доступны,
продолжение повторяет те же байты. Manifest создаётся после подтверждения
и получения всех файлов. Публичные URL, MIME, index и fallback проверяются
отдельно до изменения ArNS.

Ключ используется только владельцем из приватного локального файла вне
checkout, release и journal. Он не передаётся в чат или GitHub Actions.
Actions сохраняет точный принятый пакет и публичную оценку, без подписи/upload.

## Что проверено локально

- Повторная стандартная production сборка с TypeScript и проверкой границ:
  **10 JS assets, 340 включённых модулей, 8 файлов автономного восстановления**;
  `mandatorySejireService: false`.
- Новое native-only восстановление: **8 синтетических сценариев**, включая
  недоступный индекс, пользовательский узел, поддельный header, известный ID
  и отсутствие сетевых запросов при неверных словах/отменённом поиске.
- Полный независимый backup/finalization: **18 сценариев**, включая историю,
  несколько деревьев, отмену, late completion и изменение cache другой вкладкой.
- Основной direct writer: **21 сценарий** со сбоем подписи/хранилища/сети,
  запретом повторной подписи при неизвестном результате и проверкой all-chunk
  доставки. Дополнительные native boundary/history suites входят в CI.
- Native publisher и exact-CI ZIP acceptance проверены синтетическим узлом
  и эфемерными RSA-4096 ключами. Независимое ревью устранило три проблемы:
  ACK подавлял нужный replay, локальные provenance assertions не были связаны
  с реальным CI ZIP, а ремонт уже подписанной операции зависел от свежего
  GitHub HEAD. Тесты покрывают исправления; фактические окончательные totals
  доступны в CI.
- Dev recovery middleware проверен настоящими локальными HTTP-запросами:
  8/8 файлов совпали с decoder, MIME/HEAD корректны, запись и посторонние
  пути запрещены. Production набор проверяется отдельно.
- Полный web lint завершился без ошибок; ранее существовавшие предупреждения
  React hooks сохранены и не объявляются нулевым lint audit.

В локальной среде CLI `tsx` ограничен IPC, поэтому для указанных selftests
использовался эквивалентный `node --import …/tsx/dist/loader.mjs`. Штатные npm
команды, все браузерные сценарии, PDF regression, OS-isolated offline decoder,
dependency audit и публичные native API/CORS checks должны завершиться в
полном GitHub CI именно для окончательного source. Браузерная collection не
выдаётся за выполнение.

## Что необходимо до публичного cutover

1. Принять точный artifact успешного CI для замороженного source/attempt.
2. Владелец просматривает адрес кошелька и текущую native AR quote, выбирает
   лимит и выполняет загрузку на постоянном диске; сохранить journal и receipt.
3. Проверить подтверждённые native headers и реальные bytes всех файлов,
   manifest paths, Content-Type, корневой index и fallback.
4. Выполнить реальную wallet-попытку на синтетической семье и полное
   восстановление в чистом браузере, отдельно — offline из encrypted kit.
5. В Console проверить права на уже купленное имя, записать прежний Target,
   изменить только `@` на проверенный manifest и сверить публичные файлы по имени.

Эта последовательность не удаляет прежние версии Arweave. Обновление имени
переключает указатель. Старый оплаченный
`AtwLYx509C9jWIFKUNg7dy1GSgiaDbXVK1YEQbBWfHY` остаётся отдельным обязательством
до фактического получения и восстановления его исходного ciphertext.
Ни новый сайт, ни новый AR-save не заменяют прежнюю квитанцию или платёж.
