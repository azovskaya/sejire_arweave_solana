# SEJIRE — аудит кода перед публикацией на sejire.ar.io

Дата: **25 ноября 2026 года**, часовой пояс владельца — Asia/Almaty.

## Решение

**NO-GO для открытого запуска требуемого продукта: Solana Mainnet + промокод + управление в админке, без обязательного Cloudflare.**

Аудит выявил и исправил ошибки, которые мешали сохранности полного архива, корректному продолжению оплаченных операций и достоверному отображению результата. Исправления находятся в отдельной ветке и черновике [PR №11](https://github.com/azovskaya/sejire_arweave_solana/pull/11). Это существенное улучшение проверяемого кода, но оно не заменяет настройку и приёмку действующего сервиса. Полный CI окончательного кандидата **успешен**: 77 шагов PASS, один диагностический шаг штатно пропущен, 320 успешных браузерных прогонов в 14 наборах. Проверенный merge tree совпадает с деревом кандидата.

Готовность нельзя установить одним входом владельца в ar.io Console или успешной загрузкой HTML/JS. Нужны согласованный профиль frontend, работающий сервер для SOL/promo, его казна и журнал, действующий административный вход, подтверждённое восстановление и проверенный публичный manifest. Абсолютная гарантия отсутствия будущих ошибок этим аудитом не предоставляется.

## 5. Денежная логика и промокоды

В просмотренном общем денежном коде суммы представлены целыми lamports/строками и вычисляются через BigInt. Сервисная цена — **0.03 SOL**, с отдельной сетевой комиссией. Добровольный взнос имеет отдельное действие/согласие и нулевое начальное значение; технический диапазон u64 не выдается за коммерческий лимит пожертвования.

Проверки связывают оплату с сохранённой policy, сетью, payer, reference, суммой, получателями и подготовленным сообщением. Signed SOL bytes сохраняются до relay. Потерянный ответ не создаёт новую оплату. Подтверждённая оплата сама по себе не доказывает доставку архива.

Изменение получателей и промокода влияет на новые предложения. Принятые заказы продолжают исходные реквизиты и revision. Промокод не является деньгами: AR за хранение расходуются из казны оператора. Смена кода не пополняет эту казну и не отменяет уже принятые обязательства.

Текущий предел paid/promo — **512 KiB зашифрованного envelope целиком**. Большой архив отклоняется до admission/оплаты. Наличие более высокого общего schema-лимита или изменение только переменной окружения не снимает этот API-предел.

## 6. Что ещё препятствует требуемому публичному запуску

### 6.1. Нет одного принятого пакета с требуемой комбинацией функций

Independent release действительно исключает обязательный backend, но также исключает SOL/promo/admin. Исторический funded builder умеет принимать HTTPS API origin, однако по умолчанию использует прежний Worker; старый permaweb release contract и offline recovery не образуют готовый принятый non-Cloudflare funded-профиль.

Нужен отдельный целевой funded release с реальным API origin, соответствующей admin-конфигурацией и автономным recovery-kit. Проверки independent-профиля не следует ослаблять или переименовывать, чтобы выдать его за другой продукт.

### 6.2. Production Linux API и данные эксплуатации ещё не приняты

В репозитории есть проверенный адаптер, но в этом аудите не предъявлены и не приняты конкретные production HTTPS endpoint, persistent disk, backup/restore, CORS, trusted ingress и доступ владельца. Загрузка frontend в Arweave не запускает Node.js/SQLite сервер.

Тест SIGKILL/restart доказывает восстановление локального adapter, но не подтверждает автоматический restart, сохранность диска и резервные копии у ещё не выбранного/не проверенного провайдера. Нагрузочная ёмкость конкретного размещения также не установлена.

### 6.3. Promo не имеет автономного продолжения, эквивалентного paid alarm

Paid jobs продолжаются через alarm. Promo требует явного retry пользователя или admin reconciliation. После аварии до сохранения подписи `RESERVED` освобождается администратором лишь после установленной десятиминутной выдержки. Это сохранение осторожной учётной модели, но не полностью автономное обслуживание.

### 6.4. Пополнение AR не увеличивает сохранённый treasury ceiling автоматически

`TreasuryGuard.effectiveBalance()` использует консервативный минимум прежнего ceiling и наблюдаемого баланса. В текущем admin/reconcile нет проверенного механизма повышения этого ceiling после нового поступления AR. Нельзя обещать неограниченное продолжение сервиса простым refill или сменой promo-limit. Нужен отдельно проверенный порядок учёта пополнения с сохранением прежних расходов, reservations и signed obligations.

### 6.5. Администрирование требует доведения под Mainnet

После публикации правильного funded-профиля предусмотрены маршруты:

| Назначение | Адрес |
|---|---|
| Общий вход в админку | `https://sejire.ar.io/#/admin` |
| Промокод, фонд и соответствующие настройки | `https://sejire.ar.io/#/fund-admin` |
| Диагностика | `https://sejire.ar.io/#/admin/diagnostics` |
| Совместимость с прежним тестовым пилотом | `https://sejire.ar.io/#/save/legacy-pilot` |

Это маршруты исходного кода, а не заявление, что новый сервис уже работает на этих URL. Серверные операции требуют административного credential. Публичный `admin-lock.json`/локальный verifier защищает только интерфейс, не заменяя серверную авторизацию. Linux использует `ADMIN_TOKEN`; старые `/v1/admin/setup` и `/v1/admin/password` здесь не смонтированы.

Исторический overview явно использует Devnet-пилот. Это не полноценный реестр новых Mainnet paid orders. Нужны проверенный вход владельца, понятный учёт реальных операций и практическая проверка ротации кода на целевом API.

### 6.6. Сохраняются ограничения редактора

Два одновременно редактирующих окна используют общий draft и модель последней записи. Сохранность платежей и encrypted vault не равнозначна защите одновременных правок draft. До отдельного conflict/ownership guard следует считать допустимым только одно активное окно редактирования данного черновика.

У профиля есть 350 ms debounce. Обычные Save/Home/export/profile navigation выполняют flush; отдельный гарантированный flush последних символов при мгновенном browser reload/pagehide не реализован. Полная accessibility, переводная и визуальная приёмка всех устройств этим code review не заявляется.

### 6.7. Живое сквозное сохранение и прежнее обязательство

Не выполнена новая production-приёмка настоящим Phantom/Solflare: сохранить → дождаться подтверждения → получить фактические байты из Arweave → сверить digest → восстановить все деревья/историю в чистом браузере. То же требуется для реального промокода после admin rotation и restart сервера. Ни программный signer, ни mocked browser flow не заменяют эту проверку.

Прежний оплаченный `AtwLYx509C9jWIFKUNg7dy1GSgiaDbXVK1YEQbBWfHY` остаётся отдельным обязательством. Последняя зафиксированная read-only проверка 24 ноября подтверждала header/status, но не получение raw data. Этот аудит не объявляет архив восстановленным и не создаёт новый платёж/архив вместо него. Исходные ciphertext, signatures, receipts и журналы необходимо сохранить.

## 9. Порядок закрытия оставшихся gates

1. **Выполнено для текущего кандидата:** полный CI, commit/tree и evidence закреплены. После следующих изменений целевого release profile потребуется проверка уже его конкретных байтов.
2. Согласовать и подготовить реальный non-Cloudflare API: hostname, постоянный диск, журнал, backup, restart, CORS и административный вход. Публичные адреса получателей сверяет владелец; секреты вводятся им в предназначенное хранилище.
3. Довести целевой funded release profile, promo continuation/refill и административный учёт. Добавить в этот пакет автономное восстановление; ограничения размеров и редактирования должны соответствовать обещаниям продукта.
4. Пройти живую приёмку SOL и промокода на синтетическом дереве, с реальным кошельком владельца и отдельно просмотренными расходами. Проверить restart, rotation и восстановление в чистом браузере по полученным байтам.
5. Закрепить конкретный проверенный frontend artifact и его SHA-256. Сверить отсутствие секретов, полный manifest, index/fallback, assets, recovery files и MIME.
6. Показать владельцу конкретную стоимость загрузки. Выполнить один upload; при неизвестном ответе проверять исходную попытку, не создавать слепо новую. Цена quote не является provider-enforced абсолютным hard cap.
7. До переключения имени получить публичные файлы по manifest ID и сверить каждый digest, root и fallback. Сохранить прежний Target для возврата.
8. Владелец/действующий controller подтверждает изменение корневой записи `@` существующего `sejire` на проверенный manifest. После TTL проверить сам `sejire.ar.io` и действующие сохранения/админку на этом origin.

Проверка прав на имя возможна сейчас через [карточку sejire](https://console.ar.io/domains/sejire). Фразы кошелька и слова восстановления архива SEJIRE — разные секреты; для аудита и согласования нужны публичные адреса/статусы, а не сами слова.
