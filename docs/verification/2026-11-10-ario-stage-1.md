# Подготовка к ar.io — этап 1A: контролируемый выпуск Worker

## Граница изменения

Исходная ветка `feat/promo-funded-preservation`: `f058ec062ddaacf944e31472b0adaa5931342b57`.
Проверенный через GitHub файл `gh-pages/build-provenance.json` указывает на исходный выпуск `02983df5488d289e7206281b1af2490ee6e45449`, CI `42043325561`, артефакт `13424237198`.
Прямой публичный HTTPS provenance в этом окружении прочитать не удалось; это не свежая проверка доступности сайта.

Работа выполняется в отдельной ветке. Production Worker, Pages, ArNS, получатели, цены, бюджет, база заказов и пользовательские данные не меняются этим PR. Локальная рабочая папка владельца недоступна агенту и не изменяется.

## Изменение

- Удалён автоматический Worker deploy по push: только ручной workflow_dispatch с подтверждением DEPLOY.
- Нужны ID и номер попытки полного успешного SEJIRE checks для точно выбранного текущего SHA производственной feature-ветки.
- Read-only gate проверяет репозиторий, источник, workflow, SHA, ветку, событие, результат, jobs и steps; ошибки сети и недостающие доказательства закрывают выпуск.
- Повторная проверка CI/ветки выполняется непосредственно перед deploy; изменившаяся попытка CI или HEAD отклоняются.
- Сохранены все прежние серверные/runtime/build проверки. Добавлены обязательные свежие npm audits production-зависимостей с порогом high.
- Уже выполняющийся deploy не отменяется новым запуском. Cloudflare credentials доступны только последнему deploy-step.
- Все старые проверки в checks.yml сохранены; добавлены offline-регрессии gate.

## Проверки

Локально Node 22.16.0: `node --test scripts/worker-release-gate.test.mjs` — 53/53 PASS. Проверены YAML parsing и `node --check`.
Тесты используют вымышленные метаданные и подставной fetch; никаких реальных кошельков, архивов, платежей или deploy.
Полный CI для нового коммита должен быть проверен по отдельному GitHub run; результаты старых коммитов не переносятся на этот PR.

## Что пока НЕ закрыто

Это этап 1A, не завершение всей миграции. Защита действует в production только после принятия изменений в соответствующую ветку. Аудит зависимостей не исправлен этим PR: существующие замечания могут обоснованно блокировать новый release. Принудительного обхода gate нет.
Отдельные этапы: редактор (undo/последний ввод/две вкладки), пределы архивов, старые резервы, независимое восстановление, переносимость статического артефакта и проверенный переход ArNS. Платные uploads и изменение имени требуют оценки конкретного выпуска и разрешения владельца.
