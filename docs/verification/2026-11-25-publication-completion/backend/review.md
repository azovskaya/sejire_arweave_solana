# Backend: завершение кандидата, 25 ноября 2026

Изменения локальны в `feat/funded-portable-release-20261125`. Коммит, push, deployment, чтение production secrets и реальные транзакции этим агентом не выполнялись. SHA-256 исходников и результаты команд находятся в `summary.json`. Это подтверждение работы кода на синтетических данных, а не приёмка production.

## Что завершено

**Автономный promo.** `fund/ledger.ts` добавляет `fund_jobs` без изменения прежних orders, parent links, событий и signed bytes. Незавершённые исторические заявки получают задания при открытии ledger. Lease исключает двух исполнителей; следующая попытка сохраняется в SQLite с backoff 15 секунд — 5 минут. `fund/runner.ts` выполняет подпись только когда у принятой заявки ещё нет сохранённого TX. Событие SIGNED записывается до первого сетевого POST; затем разрешены только прежняя транзакция и её исходные chunks. Смена/отключение промокода и закрытие браузера не прекращают уже принятое обязательство. Неопределённый результат сохраняет reservation. GET заказа не подписывает и не отправляет bytes.

`checkout/alarm.ts` обслуживает обе очереди: завершение paid не удаляет wake-up promo и наоборот. В Linux сетевой alarm не держит HTTP-очередь; SQLite transactions остаются синхронными, а lease защищает исполнение. `Promise.allSettled` удерживает lifetime всех одновременно начатых jobs до shutdown. Сигнал закрытия дожидается requests/queue/background перед закрытием business DB и kernel writer guard.

**AR-пополнение.** `treasuryTopups.ts` хранит immutable intent и append-only audit. Prepare фиксирует conservative ceiling, сумму и наблюдавшийся head. После фиксации baseline сервер генерирует случайный nonce 256 bit, неизвестный клиенту заранее; в ответе это `transferTag = {name: "SEJIRE-Topup-Intent", value: <64hex>}`. Новый native AR transfer обязан включать именно этот подписанный tag. Confirm проверяет RSA-подпись, ID, native format2, отсутствие data, точную сумму/получателя, отличного от казны sender, новое block height, минимум 12 confirmations и согласие двух фиксированных public nodes. SQL в одной transaction проверяет revision/CAS, уникальность TX и nonce, увеличивает ceiling ровно на proved amount и сохраняет proof. Lost ACK/retry не дают повторного credit. Ревизии расходов и неисполненные holds сохраняются. Физический ceiling не является квотой: top-up не сбрасывает spent и не увеличивает promo/paid budget cap.

**Обнаруженное на независимом review и исправленное.** Один только порядок balance → /info, даже на двух gateway, не является доказательством coherent snapshot: balance мог уже включать перевод X, а оба /info — отставать. Добавлен exact counterexample: баланс9000 уже включает TX на height101, оба head=100. Прежний TX без будущего nonce отвергается и ceiling остаётся9000; новая подпись с выданным nonce увеличивает ceiling ровно на1000. Старые prepared intents без nonce не переиспользуются и дают `topup_legacy_intent_requires_review`; уже credited history не переписывается. Обычный перевод AR без signed tag не подходит для этого процесса. Owner sending path должен явно создавать tagged native transfer; один memo в комментарии или произвольный txId его не заменяет.

**Один owner transfer через разные браузеры.** Durable server claim сохраняет exact unsigned native TX до открытия wallet.sign. Claim не истекает автоматически; другой claim/unsigned payload для того же intent отвергается. Signed commit проверяет owner/target/quantity/reward/anchor/data/nonce, RSA-подпись и исходные tags; допустимы лишь дополнительные уникальные bounded Signing-Client/Signing-Client-Version. Сохраняется единственный signed TX, доступный после restart/из другого браузера через защищённый GET. Confirm не принимает другую транзакцию и не закрывает неизвестную ещё не сохранённую подпись. Backend не подписывает и не отправляет owner payment. Reciprocal read-only review frontend `treasuryTransfer.ts`/Store прошёл: поздняя подпись попадает только в IndexedDB, credentials/network callbacks после logout не сохраняются, server signed/readback предшествует broadcast.

**Админка и readiness.** `/api/fund/admin/paid-orders` авторизуется сервером, показывает authoritative v2 orders и отдельные totals для Mainnet/Devnet. Pagination ограничена100. Ответ строится по разрешённым полям и не содержит ciphertext, session/hash capability, idempotency owner key, signed raw/message, JWK или RPC credentials. Totals денег включают только committed payments. `updatedAt` — максимум известных сохранённых timestamps (создание, подготовка, proof, receipt); старые строки не получают выдуманную дату изменения.

`/api/fund/admin/service-readiness` — GET без подписи/upload, с точными configuration blockers/flags/revisions; `scope: configuration` не утверждает работоспособность сети или миграции. Существующий read-only `/admin/readiness` теперь запрашивает quote для полного configured max archive (до524288bytes), а одним ledger read получает shared holds, guarded ceiling и effectiveAvailableWinston=min(остаток promo quota, guarded balance−shared holds). Gross wallet balance не выдаётся за доступный фонд. Public `/healthz` подтверждает процесс+SQLite и возвращает только schema/status/runtime/sourceCommit; это не платёжная готовность. Admin status/readiness может работать до promo activation. Secret вводится только через owner/operator configuration, не в исходниках и не в браузерном localStorage.

**Linux operational gates.** Наличие `<canonicalDbPath>.restore-review.json` запрещает запуск ДО writer/database/alarm (`linux_restore_review_required`); marker никогда не удаляется автоматически. Новый `SEJIRE_TRUSTED_PROXY_CIDRS` включает IP-only XFF parsing справа налево, только если socket peer входит в явный CIDR allowlist. По умолчанию forwarding игнорируется; `/0`, wildcard, malformed/слишком длинные цепочки не доверяются. HTTP test проверяет фактический rate bucket и игнорирование spoofed CF header. Реальные ingress CIDRs должен сообщить hosting operator.

## Внешние gates

Не выполнялись: реальные Phantom/Solflare approvals, Mainnet SOL payment, native tagged AR top-up/12 network confirmations, production signer, permanent upload, чистое восстановление опубликованного архива и owner-level Cloudflare→Linux migration. Нужен постоянно работающий single-writer server с persistent disk/backup, проверенным ingress/CORS, восстановлением snapshot и мониторингом незавершённых jobs. Спящий free-tier host не обеспечивает автономное продолжение. Подписанная заявка при неполученном доказательстве не заменяется автоматически новой оплатой: она остаётся обязательством оператора. Encrypted envelope по-прежнему ограничен512KiB.

Ни пустая Linux SQLite, ни зелёный health/config check не переносят прежние обязательства. Mapping29 app tables, private snapshot codec, конкретный offline importer и процедура переноса перечислены в `legacy-migration.md`. Importer проверен на exact old payload/token-hash/holds/event readback и не может запустить, перезаписать live destination или снять review barrier. Настоящий source freeze/export/legacy KV inventory остаётся owner prerequisite, а не выполненной операцией. Независимый review importer другим агентом не нашёл новых blockers; source quiescence явно внешняя.
