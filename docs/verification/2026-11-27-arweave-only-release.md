## Действующая архитектура

Обычные `npm run web` и `npm run web:build` выбирают независимое приложение.
Редактор, история, шифрование и расшифровка выполняются в браузере. Новые
зашифрованные архивы подписываются Arweave-кошельком пользователя и отправляются
через native HTTP API. Узлы заменяемы; пользователь может выбрать совместимый
HTTPS-узел, и этот выбор не вызывает скрытого перехода к чужому индексу.

В production-графе нет серверного API SEJIRE, Cloudflare runtime, checkout/fund
клиентов, Goldsky, hosted AO transport или Turbo upload/payment SDK. Граф
проверен по всем **340 включённым модулям и 10 JS chunks**, включая ленивые
части приложения. Локальные функции истории не выдаются за сетевой AO.

Выпуск содержит **8 файлов автономного восстановления**. Полный encrypted kit
сохраняет деревья и историю. Восстановление возможно по локальному файлу и
архивным словам SEJIRE; получение по transaction ID дополнительно требует
доступности сетевых байтов. Ключевые форматы не менялись: `sejire/envelope/v1`
и `sejire/v0.3`. Внешние фотографии по URL не встраиваются в архив автоматически.

### Оплата, промокоды и администрирование

Новое сохранение оплачивается пользователем **в AR по текущей storage fee**.
Прежняя комиссия 0.03 SOL, серверный промокод и парольная админка не входят
в этот выпуск. Автоматического спонсирования native AR здесь нет; секрет
казны не помещён в общедоступный JavaScript. Безопасное спонсирование требует
отдельно реализованного протокола и не объявляется готовым самим удалением сервера.

После публикации страница `https://sejire.ar.io/#/protocol` объясняет текущую
модель. Старые `#/admin` и `#/fund-admin` открывают это объяснение. Управление
уже купленным именем остаётся у владельца в
[Console](https://console.ar.io/domains/sejire). Старый funded-код и его
журналы сохранены для совместимости и предыдущих обязательств, но не включены
в новую публичную сборку.

### Отдельная зависимость имени

Согласно текущему [описанию ArNS](https://docs.ar.io/learn/arns), реестр и ANT
имени находятся в Solana. Само приложение и семейные архивы размещаются в
Arweave; удобное имя `sejire.ar.io` имеет дополнительный слой адресации.
Прямой manifest/transaction ID сохраняется как путь доступа без ArNS.
Буквальное требование «нигде не использовать Solana, включая имя» несовместимо
с текущим устройством этого ArNS-имени; код приложения этого свойства сети не меняет.

## Порядок перехода

1. **Проверить окружение владельца.** Для одноразовой публикации нужны
   поддерживаемый Node 24.22.3, Python 3, lockfile-зависимости и постоянный
   локальный диск. CLI проверен на Linux; фактический запуск на Mac владельца
   ещё предстоит. Подготовка и проверка окружения не требуют ключа.
2. **Подготовить точный пакет.** Использовать принятый source `ab06f2d…`
   и распаковать готовый ZIP в отдельный каталог, сохранив структуру.
   Проверить SHA-256, затем выполнить `permaweb:plan` и свежий `permaweb:quote`.
   Если для чтения исходного GitHub artifact потребуется авторизация,
   она выполняется владельцем локально; токен не передаётся в чат.
3. **Проверить кошелёк и лимит.** Владелец выбирает свой AR-адрес и общий
   cap по свежей оценке. Native CLI использует приватный JWK только локально,
   вне checkout, release и journal. Seed-фраза или содержимое ключа не нужны
   ассистенту. Обычным посетителям сайта JWK/CLI не нужны: они подписывают
   сохранение совместимым Arweave-кошельком через интерфейс.
4. **Выполнить native upload.** Для выпуска создать отдельный приватный
   постоянный journal. Намерение подписи сохраняется до signer, подписанные
   bytes — до первого POST. Общий cap нельзя увеличить незаметно; неизвестная
   подпись блокирует новую. При обрыве использовать прежний journal и ID.
5. **Проверить доставку.** `check` только читает сеть; `replay` повторяет
   уже подписанные заголовки и все chunks без ключа/GitHub; `resume` может
   подписывать оставшиеся файлы после повторной проверки exact-CI ZIP.
   Manifest создаётся после подтверждения и фактического получения всех файлов.
6. **Проверить сайт по manifest ID.** До изменения имени проверить каждый
   файл, Content-Type, index, fallback, открытие редактора и полный реальный
   save/recovery на небольшой синтетической семье. Отдельно открыть encrypted
   kit и decoder без сети. 12 архивных слов вводит только сам владелец.
7. **Обновить существующее имя.** Открыть Console, проверить Owner/Controllers,
   записать прежние Target и TTL. В Records отредактировать только `@`, указав
   новый проверенный manifest ID. Покупать имя заново или менять владельца
   для обычного обновления не требуется. Комиссия имени подтверждается отдельно.
8. **Принять публичный переход.** После обновления проверить root/JS/CSS,
   пути восстановления и реальные bytes через `sejire.ar.io`, сверить
   фактическую запись имени. Сохранить новый и старый manifest IDs, journal,
   package hashes, квитанции и автономные recovery copies.

Команды и поведение CLI подробно описаны в
[INDEPENDENT_RELEASE.md](../INDEPENDENT_RELEASE.md). Официальный порядок
изменения записи: [ar.io Console guide](https://docs.ar.io/build/guides/working-with-arns/buy-manage-arns-console).

## Какие сведения нужны от владельца

Для следующего шага достаточно публичных данных: адрес Arweave-кошелька,
текущие Owner/Controllers/Target/TTL имени и версия ОС/Node/Python на компьютере
для публикации. Позже владелец выбирает лимит AR и лично выполняет подписи.
Пароль, 12/24 слова, приватный JWK и локальный GitHub token не передаются
ассистенту, в Git или в публичный пакет.

Если Wander уже восстановлен, его нужно только открыть и разблокировать.
При восстановлении существующего аккаунта слова вводятся в установленном
расширении Wander; официальная инструкция:
[Add an existing wallet by Seedphrase](https://www.wander.app/help/browser-extension---onboarding-add-an-existing-wallet-by-seedphrase-2).
Официальная документация описывает [JWK keyfile](https://www.wander.app/help/what-is-a-json-keyfile)
как приватный ключ с доступом к средствам. Его экспорт и хранение выполняются
локально владельцем. Не путать его с
[Wander Connect Recovery File](https://www.wander.app/help/what-is-a-wander-connect-recovery-file):
последний хранит долю ключа, а не полный native RSA JWK для этого CLI.

## Что ещё не подтверждено реальной сетью и владельцем

Новая on-chain публикация, работа настоящего расширения в платном save,
реальное восстановление новой записи в чистом браузере, фактические права
на имя и его обновление остаются этапами живой приёмки. Ответ узла о числе
подтверждений не является собственной light-client проверкой консенсуса.
Доступность из каждой сети в любой момент и сохранность через 200 лет не
могут быть гарантированы этим CI.

Лимит нового native envelope — 10 MiB. Индекс не доказывает полноту истории.
До переключения имени сохранить данные прежнего браузера: смена origin
не переносит IndexedDB/localStorage автоматически. Мгновенное закрытие
браузера и несколько редакторов остаются причиной хранить явные encrypted
backup copies, а не полагаться только на текущий draft.

Прежний оплаченный `AtwLYx509C9jWIFKUNg7dy1GSgiaDbXVK1YEQbBWfHY` остаётся
отдельным незавершённым обязательством до получения и восстановления его
исходных bytes. Успешная проверка другого fixture не закрывает это обязательство.
Старые ciphertext, подписи, квитанции и журналы не удалялись и не заменялись
новой оплатой.

**Зафиксированное состояние:** код и точный пакет приняты; AR quote получена;
постоянный backend не требуется; новые подписи, расходы, публикация и ArNS
изменения не выполнялись. Main и старый опубликованный сайт этим этапом не изменены.
