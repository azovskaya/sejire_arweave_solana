## Реализовано

- Точная integer арифметика SOL/USDC, canonical decimal input, precision/u64 проверки. Нет коммерческого потолка добровольного взноса; проверены миллион и миллиард USDC. Повторное подтверждение больших сумм — отдельный predicate, не запрет или spending allowance.
- Неизменяемый order с сетью/активом/получателями/payer/reference/сроком/версией серверной ценовой политики. Preservation требует exact-envelope SHA-256 и byte count; contribution-only имеет нулевую услугу, положительный взнос, без архива. Нет встроенного лимита 512 KiB.
- Цена услуги, fund contribution и SOL network fee разделены. Типы TurboFundingCap и TreasuryControls независимы от правил приёма взноса. Прежние 0.01 SOL direct Turbo cap не изменены.
- Validator: finalized successful evidence, genesis/network, payer/signer, mint/program/decimals, точная сумма, recipient/reference, transfer locator; назначения не получают весь объём транзакции повторно. Принимается только ограниченный checkout template, дополнительные переводы отклоняются.
- Pending signature фиксируется до RPC-reader; неизвестный/потерянный/нефинальный результат остаётся требует сверки. Подмена подписи для незавершённого заказа запрещена. Новый платёж не создаётся.
- Memory atomic contract: order/reference uniqueness, unique transaction/instruction credits, атомарная смена состояний в одном isolate, detached snapshots. 32 одновременных подтверждения дают один credit, retry после потерянного commit-response — already-credited.
- ADR рекомендует USDC для хакатонного checkout, SOL для gas; окончательный production-выбор не объявлен. Production custody модель и dashboard/Campaign спецификации подготовлены; treasury, promo API и dashboard не создавались.
- Checks workflow расширен на feature branch, sponsor typecheck, lint и archive measurement. Только `contents: read`, без publication. Deploy workflows не менялись.

## Размеры: измерение, не обещание безлимитных версий

Параметры и bytes сохранены в [archive-sizes](2026-09-30-archive-sizes.json). Использован настоящий tree engine и текущий envelope AES-GCM, Unicode names, parent relationships, notes, media references; commit ids/time канонизированы только в synthetic fixture для повторяемости размера. Случайный AES key находится только в памяти и не выводится/сохраняется. Recovery words/кошельки не создавались.

| Деревья | Людей в каждом | Полных commits на дерево | Plain bytes | Envelope bytes |
|---:|---:|---:|---:|---:|
| 1 | 20 | 1 | 19 001 | 25 541 |
| 2 | 100 | 5 | 554 946 | 740 137 |
| 4 | 250 | 10 | 5 092 480 | 6 790 181 |
| 2 | 1000 | 3 | 3 709 986 | 4 946 857 |

Каждый vault включает также draft. Full snapshot history существенно влияет на объём. Текущая модель media хранит ссылки, не включает фотографию в envelope. 1/5/20 MiB embedded attachments рассмотрены только как нижняя оценка base64-роста, не как реализованный формат. Двойное base64 внутри будущего JSON может увеличить размер ещё больше. Продуктовый лимит нельзя выводить из количества людей.

**Предварительный кандидат для MVP — 2 MiB envelope без встроенных медиа**, чтобы не отсечь пример из двух деревьев/пяти версий. Это предложение, не установленный cap: production price, реальный signed overhead, quote limits, paid acceptance и восстановление больших файлов должны обосновать итоговую политику. Более крупные fixtures уже подходят под существующий технический импортный предел 10 MiB; этот предел и старые форматы не изменены. Размерная политика будущего сервиса/кампании версионируется отдельно от схемы order.

Test Turbo ответ: `GET https://payment.services.ar-io.dev/v1/price/bytes/744233` → HTTP 200, `winc=9314856308`, adjustments empty. Это тестовый расчёт для envelope 740137 + estimated overhead 4096, **не оплаченная загрузка и не доказанная production-себестоимость**. 4096 — оценка, не измерение подписанного item. ## Границы A1

Нет HTTP checkout маршрутов, сырого RPC декодера, реального signer, persistent adapter, казны, бюджета campaign, выдачи codes и загрузчика нового checkout. Нормализованные evidence — внутренний trusted port, не клиентский JSON. До live validator нужны exact raw instructions, loaded addresses, token account owners/authority/program, configured genesis и finality. Формат digest валидируется, но исполнение в следующем этапе обязано повторно вычислить его из ciphertext.

Memory adapter проверен только в одном JS isolate. Restart/crash/backup restore/multi-process race и сохранение незавершённой операции — NOT RUN. Перед production нужны durable unique constraints/transaction credit+state, begin до RPC, потеря ответа до/после commit, отсутствие повторного зачёта после перезапуска. Крупный входящий вклад не увеличивает разрешение операционного сервиса.
