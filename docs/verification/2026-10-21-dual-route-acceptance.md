## Почему Solana блокирует выпуск

В [package.json](../../package.json) `native:build` фиксирует `VITE_NATIVE_SOL_MAINNET=0`. [PreservationV2.tsx](../../apps/web/src/components/PreservationV2.tsx) корректно показывает недоступность для editor envelope. Простое включение этого флага открыло бы прежний пилот с конкретным devnet payer и фиксированным архивом 28 365 bytes; он также требует казначейский Wander. Это не общий путь сохранения нового пользовательского дерева.

Отдельный checkout API и RPC reader пока используют devnet, а его archive executor — sandbox `ar-io.dev` и `winc: "0"`. Цена уже задана: **0.03 SOL**, дополнительный взнос по умолчанию 0, комиссия Solana отдельно. Production SOL recipients и отдельный paid AR budget не назначены. Общий платный путь с сохранённым ciphertext до оплаты, durable исполнением, подтверждённым Arweave результатом и завершением редактора описан в [плане реализации](../PAID_SOL_IMPLEMENTATION_PLAN.md), но ещё не реализован.

## Условие публикации

Для разрешённого владельцем переноса сначала нужны реализованный и принятый общий SOL путь, подтверждённое завершение promo-заказов в Fund и проверенное восстановление обоих способов. Реальная wallet acceptance остаётся отдельным фактом: её не заменяют программный signer или подставленные RPC-ответы.

Существующий `scripts/deploy-permaweb.sh` заново собирает приложение с default `VITE_PUBLISH_MODE=self` и не меняет ArNS. Для переноса принятого выпуска потребуется публикация точного проверенного artifact без пересборки, проверка опубликованных bytes до изменения имени и затем проверка `sejire.ar.io`.

Этот этап добавляет только результаты проверки и запись для продолжения. Production flags, приложение, Worker, ArNS и прежние заказы не менялись. Новых реальных order POST, SOL платежей, Arweave подписей или отправок — 0.
