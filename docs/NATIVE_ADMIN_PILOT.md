# Native SEJIRE administration and Arweave manual pilot

The new path uses native SOL payments and **Arweave format-2 transactions** through the already installed arweave-js 1.15.7. No Turbo credits/payment/upload API or mandatory cloud account is used by this path. Legacy Turbo reads, receipts and the previous optional payment path remain compatible. The earlier Turbo preflight is historical and its quote does not apply here.

## Owner interface

The first screen is **SEJIRE → Центр управления**. New installations see a six-step setup wizard (network, Phantom manager, SOL service treasury, SOL contribution fund, AR reserve, review). Creating your own genesis signs the unchanged configuration and explicit acceptance, verifies both, and downloads `sejire-trust-anchor.json`. Keep this public trust file separately from the signed configuration. This is your own local configuration, not global ownership or Arweave publication.

For an existing project, import an independently obtained trust file and the signed configuration; never accept an unknown chain merely because its hash is supplied beside it. The Overview shows only checked public balances and verified imported-job accounting; missing values say “Нет данных”/“Не проверено”. Device-local counts are labeled and are not a global service dashboard. Manager confirmation uses a signed, nonce-bound UI challenge; all actual changes still require the previous authority threshold. Address/price changes affect only new orders.

Wallet roles are separate cards. Settings and wallet replacements produce drafts, never automatic fund movement. Orders use a table and archives show separate payment/sign/upload/inclusion/hash stages. AR quotes are displayed in AR; SOL is never automatically converted. Availability still means the existing time-limited manual declaration, not a new scheduler. **Расширенные настройки** is closed by default and retains trust hashes, JSON/chain imports and exports, RPC/nodes, raw budget/history, IDs and gateway selection. The manual queue, signed config model and direct format-2 path are unchanged.

## Open and configure

Public temporary preview: https://azovskaya.github.io/sejire_arweave_solana/native-admin/ and admin https://azovskaya.github.io/sejire_arweave_solana/native-admin/#/admin . No local server or GitHub visitor account is required. IndexedDB remains a device-local cache; on another computer import the signed configuration/workspace and independently trusted genesis fingerprint. No configuration has been published in Arweave by this deployment. The Pages workflow verifies the accepted build artifact SHA/digest, preserves the existing Pages tree, and checks the actual public interface with no network fixtures. Mainnet broadcast and configuration publication stay disabled.

Use the Ubuntu CI `native-admin-build` artifact, extract the static files and serve them with an ordinary local HTTP server. Open `http://localhost:4173/#/admin`. This does not publish a site. In a supported development environment: `npm ci --prefix apps/web`, `npm ci --prefix apps/sponsor`, `npm run native:dev`, then `http://127.0.0.1:5173/#/admin`. Catalina modern Vite binaries remain unsupported; do not replace global tools.

In **Кошельки**, enter public addresses for Основная казна SEJIRE (SOL service income), Фонд памяти поколений SEJIRE (SOL contributions), and AR-резерв основной казны SEJIRE (separate operational AR). SOL and AR networks are separate. There is no automatic SOL→AR conversion. Default devnet recipients are test-only; they are rejected as mainnet recipients. The mainnet test wallet from the previous preflight is not automatically assigned a role.

The default price is 30,000,000 lamports (0.03 SOL). The contribution field means an additional amount, initially zero. Thus total 0.10 SOL = 0.03 service + 0.07 fund; total 1 SOL = 0.03 + 0.97. Donation-only has no archive or service payment. Fees are separate, with u64 technical precision limits and explicit large-amount confirmation; there is no commercial contribution cap.

Enter authorized **public Solana manager keys** and configuration-signature threshold. Sign settings using Phantom and, for initial authority/new keys, sign explicit acceptance. Every signature binds SEJIRE, environment, nonce, version and previous hash. A change needs the previous configuration's threshold; new-key acceptance does not replace old-authority approval. This is NOT a Solana treasury multisig. Address rotation does not transfer funds or mutate old orders.

Before activating genesis, independently verify/pin its SHA-256 with the authorized owner. Enter that fingerprint in **Доверенный genesis SHA-256**; do not trust a hash merely because it accompanies an unknown file. The first visitor is never owner. Export/import signed drafts to collect multiple real signatures, then **Проверить и применить подписанную версию**. Import the full chain on a clean browser with the independent genesis anchor. Conflicting known histories and rollback are rejected. Discovering the globally latest version on a fresh installation additionally needs an independently trusted head/checkpoint; a valid prefix is not proof of completeness.

Configuration is a **draft/unpublished signed chain** until uploaded and network inclusion is independently checked. IndexedDB is only a recoverable cache. **Экспорт настроек, заданий и подписанной истории** is the portable workspace; keep it on another controlled device. Configuration publication is disabled in this build. Recovery from an Arweave configuration ID uses the same signature/anchor checks.

## User → administrator → direct storage

1. Existing editor/encryption flow prepares the unchanged `sejire/envelope/v1` encrypted vault. Download the portable backup first. Import the signed config and independent anchor in the native save panel.
2. Before a preservation order: a signed, time-bounded declaration of manual executor availability must be active; exact archive size, AR reserve balance and current native AR quote must fit the configured operational budget. This declaration is an operator commitment, not automatic capacity reservation. No ready executor/budget means no preservation payment offer. Donation-only does not need storage readiness.
3. Phantom signs the immutable order message, then one native SOL transaction (one or two expected System transfers plus reference). Message signing and payment approval are separate prompts. The payment amount/network/recipients/fee are shown. Mainnet SOL broadcast is disabled; devnet is the software/extension pilot network.
4. Persist pending signature and exact signed bytes before broadcast. Lost response/reload means **Сверить прежний платёж**; no new signature/payment is automatically created. Export the signed job with ciphertext and config chain. This real file handoff is **manual**, not a shared automatic queue or live AO.
5. Import the job in **Заказы и транзакции**. Verify payer signature, archive hash/size, fixed policy and signed payment template before touching pending state. **Сверить оплату через RPC** checks genesis, finalized status, raw instructions and existing validator. RPC trust is explicit: this is not a trustless bridge. Optional manager-signed observations form a hash-linked pilot audit; repeated observations do not double-credit and contradictory evidence remains a conflict. They do not grant spending authority.
6. In **Архивы**, connect an Arweave-compatible extension (e.g. Wander), read quote/balance, review the exact maximum winston, size, SHA-256 and public tags, and sign the native format-2 transaction. The configured AR reserve's signature is required, not its pasted address. No JWK/private key is requested or stored by the app. Save the signed job/export before sending: it contains the exact transaction bytes, ID and progress, but no decryption key.
7. Mainnet upload remains disabled (`VITE_NATIVE_AR_BROADCAST=0`), pending separate owner approval of a specific maximum spend. After authorized enablement, **Отправить / продолжить те же чанки** uses SDK chunk uploader and the same transaction ID. Re-import the saved attempt on another machine to resume without the first executor's private key. Never re-sign because a response is unknown. Paid SOL service income does not automatically fund the AR reserve; fund contributions are not spent for ordinary orders.
8. **Проверить включение, получить и сверить SHA-256** independently checks native status and retrieved bytes. Upload completion/HTTP 200/ID alone is not confirmed inclusion. The receipt identifies transaction ID, digest, size, protocol/encryption versions and payment signature; it does not claim settlement merely by existing. Gateway URL is not identity. Choose another or your own node.
9. The owner downloads ciphertext or the native receipt, opens **Открыть по 12 словам → Открыть из файла** in a clean browser, and enters only SEJIRE words locally. Native receipt recovery supports another gateway; file recovery needs neither API nor wallet. Old Turbo receipts/backups remain accepted. Admin/uploader cannot decrypt archives.

## Bounds of this pilot

No production wallets/resources, mainnet transfers/uploads, configuration publication, site release or ArNS change have been performed. No real Phantom/Wander acceptance or permanent Arweave settlement is established by fixtures. AO live readiness remains blocked independently.

Balances and the last 10 SOL movement records are public RPC observations, not a complete treasury audit. Net movement includes payer network fee and must not be counted as a service/fund credit. Signed payment observations maintain separate service/fund totals. Fund withdrawals/multisig and full AR spending history are not implemented; the UI states the unavailable actions rather than simulating them.

Known local history and browser locks protect retries on the same journal, including exported signed attempts. Independent offline copies **cannot establish global uniqueness or complete latest history** without a live shared authenticated journal; do not operate concurrent unsynchronized executors. The pilot requires one controlled manual queue and a current portable attempt. No new consensus/escrow mechanism is claimed.

A signer crash during preparation before the signed bytes are saved may leave an unrecorded signature; no transaction was broadcast by this client at that point. After saved signature/broadcast, reconciliation uses that exact operation. No automatic refunds or SOL redistribution exist. Funding obligations and keys remain with their owners.

Existing dependency audit failures remain release limitations. No audit policy is weakened. Plaintext, words and private keys are absent from config/jobs/audit; do not put secrets in public identifier fields. Metadata/payer and encrypted archive identifiers may be linkable to a payment in a portable receipt: keep job/receipt exports private unless you explicitly intend publication.
