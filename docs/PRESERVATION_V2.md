# Preservation V2 pilot

Branch: `feat/preservation-v2-simple`. The V2 user path is enabled in the native build by `VITE_PRESERVATION_V2_ENABLED=1`; local route: `http://127.0.0.1:5173/#/save`. Old NativeJob, orders, config, successor and recovery records remain historical and are never read by V2.

## Path and binding

1. Import the original encrypted backup file (or supply the matching encrypted envelope from the editor). V2 checks raw file size/SHA, serialized envelope size/SHA and vault ID before creating a session.
2. `saveId = SHA-256(policy version, vault ID, archive SHA, payer)`; reference is derived from `saveId`. Both remain stable across retries. The ciphertext and state live in the separate `sejire-preservation-v2` IndexedDB database. The one cross-tab lock is `sejire-preservation-v2-{saveId}`.
3. `READY → SOLANA_PREPARED → SOLANA_PENDING → SOLANA_PAID`: persist blockhash and reference before one Phantom `signAndSendTransaction` prompt. Verify a finalized devnet transaction with the expected payer, signer, reference and exactly one 30,000,000 lamport transfer to the service treasury. ComputeBudget limit/price instructions are permitted within fixed bounds; all other instructions and inner effects are rejected.
4. A lost Phantom response stays pending. The UI reconciles automatically and scans the same reference after reload. A new blockhash in the same session is allowed only when two independent devnet readers report complete reference history, every discovered transaction has finalized failure, and finalized height is beyond the old expiry. Any RPC outage, pruned history or uncertain transaction blocks another Phantom prompt. A changed active account after broadcast does not invalidate a valid finalized payment. The service charge is 0.03 devnet SOL; network fee is separate. The pilot fund transfer is zero.
5. `AR_READY → AR_SIGNED → AR_UPLOADING → AR_PENDING_CONFIRMATION → COMPLETE`: after finalized SOL, quote Arweave Mainnet and check the exact reserve, 28,365 byte archive, SHA and 4,000,000,000 winston ceiling without connecting Wander. Show exact current reward before the Save button. That button authorizes one Wander signature and the upload of the shown transaction. Persist exact signed transaction and ID before upload. On timeout/reload only those signed bytes are resumed; a lost signing response before persistence and before any upload permits another signing attempt in the same session.
6. After upload, require confirmed inclusion, retrieve the encrypted payload from a public gateway, compare size and SHA-256 and parse the envelope with the expected vault ID. Only then show Complete. Recovery words are entered locally on the separate restore screen after completion.

The UI shows only Payment, Preservation and Complete. Pending payment, upload, confirmation and retrieval advance automatically without a status button. `#/admin` in the V2 build is read-only public metadata, with no legacy operator actions or archive bytes. It never requests wallet seed phrases, wallet private keys or SEJIRE words during payment/upload. This pilot is bound to the one archive, payer and reserve approved by the owner. No real SOL/AR action is part of automated tests or CI.

## Verification and limitations

The confirmed pilot TX `T2huxIMLyfYclZH2h89Rf0IecHfFYKKaa0_3HaDP4fo` has immutable `App-Name`, `Type` and `Save-Id` tags but no `Vault-Id`. Read-only checks on 7 October found it by GraphQL ID, while public `Save-Id` tag searches returned no edges. Its `/raw/` payload is 28,365 bytes, has the policy SHA-256 and contains the policy vault ID. Clean-browser restore now tries normal `Vault-Id` discovery, then the exact pilot `Save-Id`, then this pinned ID if the tag index is empty. The ID is only a discovery hint: tags, raw size/SHA, envelope vault ID and decryption from the entered SEJIRE words must all pass. Future V2 signed transactions include `Vault-Id`; the confirmed pilot transaction is unchanged. Restore does not create a payment or upload.

`npm run test:v2 --prefix apps/web` runs synthetic policy, Solana verifier, reference recovery, state-machine and upload-resume scenarios. `npm run test:v2-browser --prefix apps/web` drives the real V2 UI and IndexedDB journal with mocked Phantom, Wander, Solana RPC and Arweave gateway: happy path, five reload points, lost wallet response, and retrieved-SHA rejection. The browser mock is excluded from the native owner bundle. Full release gate is the `SEJIRE checks` GitHub workflow on this feature branch: tests, TypeScript, lint, browser, native build, dependency boundary and retained `native-admin-build` artifact. Pages publication is a separate owner decision.

`npm run test:v2-recovery-browser --prefix apps/web` checks a clean browser profile with only synthetic 12 words, the legacy tag layout, raw gateway fallback, pinned-ID discovery when the public Save-Id index is empty, and negative network/integrity cases. The real owner's words and decrypted family data are never part of CI.

The IndexedDB journal is local to the browser profile. Starting the same save on another device without carrying a verified V2 record is unsafe and is not an authorized pilot recovery method. The owner must manually perform the real Phantom and Wander acceptance; the synthetic tests do not prove extension behavior or real settlement.
