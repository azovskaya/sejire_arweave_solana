# A2.1: trusted devnet RPC and one SQLite Durable Object ledger

Date checked: 2026-09-30. Scope approved: local code/tests + Ubuntu CI; no cloud provisioning/deploy, signature or transfer.

Decision: preserve AtomicOrderStore and implement SqliteAtomicOrderStore on existing Cloudflare sponsor platform. DurableOrderStore always chooses `sejire-checkout-ledger-v1` in one authoritative CHECKOUT_LEDGER namespace. CheckoutLedger rejects any other object identity. Unique order/reference and network/signature/instruction constraints live in the same SQLite database across ALL orders, not one object per order. Different namespaces/deployments are NOT a shared uniqueness domain: a future production operator must designate one authoritative namespace and migrate it without parallel writers. Sharding requires a separately designed global coordinator. Single-object throughput is an intentional MVP tradeoff.

SQL transactionSync wraps transaction claim, separate service/fund credits and state update. Amounts are TEXT; aggregate totals use BigInt, never SQL SUM/REAL. beginReconciliation commits and awaits storage.sync before returning for RPC. No network calls occur within SQL transactions. Pending signatures are never cleared on null/error/timeout. Old KV billing paths remain unchanged and are NOT reused for the new ledger. Stored order JSON is never updated; only pending signature, payment result and states change. Schema version mismatches fail closed.

SolanaRpcReader is server-only, devnet-only, fixed HTTPS endpoint + pinned genesis, finalized status and getTransaction checks. No arbitrary browser endpoint or normalized evidence enters the verification boundary. Supported encoding=json legacy/v0 compiled instructions; single fee payer/signer, 1–2 direct System Transfer or classic SPL Token TransferChecked instructions, one readonly reference per transfer, optional leading compute unit limit/price. v0 resolves metadata loaded addresses and lookup lengths. Token destinations are account addresses in raw instructions; historical pre/post token metadata proves their mint, program and owner before normalizing to owner recipients. Existing accounts must be owned by the payer/recipients; no delegated/multisig authority, token-2022, unchecked transfer, ATA creation, memo, nonce, unknown program or recorded CPI. ATA preparation must precede checkout; supporting ATA/CPI atomically later requires a separate explicit decoder/test expansion.

Finality does not come from transaction JSON or browser fields. Transport obtains getSignatureStatuses finalized and matching slot, then getTransaction(finalized,json,maxSupportedTransactionVersion=0). The trusted RPC remains a trust boundary: these are provider assertions, not an independent consensus/light-client proof. Only blockTime determines order inclusion window; later server receipt time does not invalidate an on-time payment.

Proof strategy: synthetic RPC responses matching official wire structures, plus actual workerd/Miniflare SQLite on disk. Two separate Node/workerd processes reopen the same storage directory. Check concurrency, rollback injection, response-loss after commit, unfinished reconciliation, cross-order replay and u64/aggregate precision. Graceful runtime disposal/reopen and injected callback failure do NOT establish cloud replication, hard power-loss recovery, PITR or distributed failover. These remain NOT RUN. No production binding/migration is configured in wrangler.toml; tests use a separate fixture entry, no public checkout routes.

Test dependencies: pinned stable Miniflare 4.20260730.0 (Node >=22), workerd and esbuild 0.28.2 dev-only. Reviewed npm metadata before lock update; local lock resolution uses ignore-scripts and never runs incompatible workerd/esbuild. Scoped compatible patches sharp 0.35.4 and undici 7.29.1 remove test-tool findings; stock clean install/runtime must prove compatibility in CI. No application SDK or cryptographic implementation replaced.
