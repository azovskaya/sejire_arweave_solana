# SEJIRE: независимое продолжение — локальный пилот

Дата: 2026-10-01. Цена сохранения — 30 000 000 lamports (0.03 SOL).
Взнос отдельный, нулевой по умолчанию, без продуктового потолка; отдельная
поддержка не требует архива или платы за услугу. SOL-комиссия отдельная.
Название «Фонд памяти поколений SEJIRE» — программа, не юридическое заявление.

## Что сейчас исполняется

`npm run protocol:serve` и в другом терминале `npm run protocol:dev` запускают
существующий интерфейс и **синтетический** localhost-исполнитель без Cloudflare,
Access, Durable Objects и SQLite. Нужен Node 22 и установленные проектные зависимости.
Заказ подписывается платежным ключом (signMessage), платеж — отдельной подписью
транзакции. Приватные слова SEJIRE не передаются исполнителю. Публичные тестовые
ключи запуска нельзя финансировать или использовать для настоящих архивов.
RPC и загрузка этого запуска подставные: он не переводит SOL и не размещает данные.

Основной код — `apps/sponsor/src/protocol/{journal,executor,http}.ts`;
канонизация — `packages/protocol/wire.ts`; UI использует прежний checkout,
формат архива и криптографию. SQLite/HTTP старого пути сохранены.

## История и доверие

Genesis закрепляет domain, process ID, хеш кода, среду Node22, devnet genesis,
политику и управляющие ключи. Его содержимое подтверждается порогом менеджеров
и независимо закрепленным creationHash. Первый отправитель полномочий не получает.
Сообщения: Order, Pending, Payment, UploadPlan, UploadResult, Policy.
Все подписываются Ed25519 над отсортированным canonical JSON UTF-8;
JSON From не удостоверяет отправителя. SOL хранится десятичными строками;
TypeScript считает BigInt, Lua-модуль считает отдельные десятичные цифры.

Один последовательный журнал связывает sequence, previous и хеш сообщения.
Воспроизведение проверяет каждую подпись/политику и использует сохраненное
свидетельство, без нового RPC. Независимо закрепленный checkpoint (head,
sequence, stateHash) обнаруживает потерю/изменение истории. Без известного
свежего checkpoint нельзя доказать отсутствие более нового хвоста.
Локальный signed export **не является аутентичным полным журналом AO**
и не доказывает доступность в Arweave. Файл запуска автоматически проверяет
подписи, но свежесть его checkpoint оператор должен сверять отдельно.

Наблюдатель — доверенный разрешенный ключ, проверяющий внешний RPC; это
не trustless-мост, а подписанное свидетельство доверенного наблюдения.
Он не меняет политику, не расшифровывает архив и не распоряжается SOL.
Противоречие остается в журнале, блокирует исполнение, не заменяет первый зачет.
В тестах все роли принадлежат одному оператору, не независимой сети.
Смена политики требует старого порога и подписанного принятия новым порогом;
старое сообщение нельзя повторить после смены epoch. Утрата всех управляющих
ключей останавливает новые управляемые операции; опубликованные архивы от
них не зависят. Скрытого master key нет.

## Граница AO — BLOCKED до живого подтверждения

`ao/modules/journal_gate.lua` — закрытый по умолчанию модуль границы,
**не готовый aos-процесс**. Он требует проверенного создания и неизменяемого
runtime-порта проверки подписей. Он не использует первый msg.From, Owner или Eval.
`ao/processes/tree.lua` и factory не включаются: их прежние публичные snapshots
и bootstrap не подходят для приватного платежного журнала.

Существующий aos допускает Eval; проверка нашего обработчика не запрещает Eval
в обход него. До публикации нужны проверяемое создание с закрепленным кодом
и средой, фактический Ed25519 verifier в выбранном AO-модуле и доказанный запрет
изменения обработчиков/Owner/Authorities вне порогового протокола. Локальный
Lua gate с заглушками runtime подтверждает лишь свою границу. Не заявляем,
что воспроизведение само предотвращает изменение работающего AO-процесса.
Живой процесс/публикация потребуют отдельного согласования сети, данных,
ключей и затрат. Сейчас AO/process ID и Arweave package ID отсутствуют.

## Заменяемое исполнение

UploadPlan хранит точный ciphertext, digest/размер в заказе, ANS-104 signed bytes
и ID. Их подпись и соответствие архиву проверяются до принятия. Второй
разрешенный исполнитель получает это задание из журнала и повторяет те же
байты/ID, без приватного ключа первого. Если уже известен прием, сначала
получает файл; повторной оплаты пользователя нет. Новый подписант/ID не
разрешается молча: нужен отдельно согласованный переход после сверки.
Политика смены ключей не дает доступа к деньгам первого исполнителя.
Для пилота оба используют отдельно обеспеченную бесплатную тестовую квоту;
в production второй требует своего операционного бюджета, не средств фонда.
AO-запись не распоряжается Solana-кошельком и не обеспечивает возврат SOL.

Платеж и загрузка не атомарны. Pending сохраняется при неизвестном ответе;
новый платеж автоматически не создается. План/receipt переживают replay.
В локальном запуске lock исключает второй writer; после аварии удалять stale
lock можно только убедившись, что прежний writer остановлен. Отказы внешней
публикации с неизвестным исходом требуют сверки, не нового расхода.

## Переносимый пакет

`npm run checkout:build && npm run continuation:package` создает
`.cache/continuation`: статический UI, автономные bundled Node22 инструменты,
код протокола/Lua, lockfiles и SHA-256 manifest. Это локальный артефакт,
не доказанное размещение Arweave. В пакет не включаются реальные ключи или архивы.
Во время восстановления Node22-инструменты не требуют npm, GitHub, CDN или домена:

```
node replay-journal.mjs journal.json independent-trust.json new-state.json
node recover-vault.mjs archive.json new-private-vault.json < private-words-file
```

Файл слов создается владельцем офлайн с правами 600, не передается оператору;
слова не указываются в аргументах/логах. Выход recovery — приватные данные, 600.
Trust-файл содержит независимые creationHash и checkpoint, не ключи.
`executor.mjs` экспортирует существующий совместимый исполнитель: оператор
подключает атомарное сохранение журнала, RPC reader, uploader и собственные
разрешенные ключи. Бандл не дает полномочий; они проверяются журналом.
Новые вычисления/загрузки оплачивает исполнитель из своего ограниченного
бюджета. Цена 0.03 SOL не оплачивает бесконечную работу сервисов.

Архив: AES-GCM-256, HKDF-SHA256, envelope `sejire/envelope/v1`, протокол
`sejire/v0.3`; derivation и wordlist включены в recovery bundle. Хранять ciphertext,
его digest, receipt/data-item ID, известные manifest/transaction ID и recovery
код независимо от сайта. Менять gateway можно без смены ID, полученные байты
сверять по digest. Нет гарантии получения при недоступности всех источников,
расшифровки при утрате ключа или исполнения новых операций через 200 лет.

повторы/конфликты, пороги, замена исполнителя. `test:protocol-browser`: прежний UI

security reachability и CI audit. Никаких audit fix --force/скрытия FAIL.
