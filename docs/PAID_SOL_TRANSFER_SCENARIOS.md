# Проверка перенесённого SOL checkout

Состояние после облачной проверки 22.10.2026: сценарии реализованы; общий `npm test`, TypeScript и native build прошли. Браузерные результаты: SOL 18/18, promo 25/25, recovery 29/29. [Полный отчёт и доказательства](verification/2026-10-22-sol-checkout-review.md). Все данные ниже должны быть синтетическими. Флаги paid и mainnet не включать. Для реального devnet платежа владелец отдельно проверяет сумму и подтверждает её в расширении кошелька.

## Выполненные автоматические проверки

1. `npm test`: существующие promo, paid, recovery и sponsor suites. Paid suite дополнен заказом `kind: contribution`: нулевая сервисная плата, положительный взнос, отсутствие archive/storage/payload/hold, одна инструкция System Program, verified payment и `preservation: not-applicable`.
2. `npm run native:build`: TypeScript и оптимизированная сборка клиента с отключёнными mainnet/broadcast.
3. Browser suite с Phantom и Solflare mock adapters пройден: подключение без заказа, серверный заказ только после кнопки, отображение параметров заказа, одна подпись, отказ 4001, смена аккаунта, недостаточный баланс, перезагрузка после каждого шага.

## Проверка сценариев и отказов

| Случай | Ожидаемый результат |
| --- | --- |
| Сохранение без помощи | Заказ с 30 000 000 lamports сервису, 0 фонду; одно SOL подтверждение; одна AR задача после верификации; история дерева и промокод не затронуты. |
| Сохранение с помощью | Вклад закрывается и открывается без потери выбранной суммы в итоговой строке; сервер фиксирует сервис и фонд отдельно; одна транзакция с двумя переводами. |
| Только помочь | Положительная сумма обязательна; сервисная плата 0, архива и AR задачи нет; после верификации показаны сумма, благодарность и ссылка Solana. |
| 0 для отдельной помощи, запятая, экспонента, более 9 дробных знаков, u64 overflow | Клиент не округляет и не открывает кошелёк для подписи. |
| Две вкладки, повтор POST, повтор verify/execute | Один journal ID/заказ, один credit на purpose, одна используемая подпись и не больше одной задачи хранения. |
| Разрыв ответа create | Локальный ID и точные bytes остаются; поиск by-key предшествует явному повтору того же запроса. |
| Отказ кошелька и закрытие после подписи | Исходная подготовка/подпись проверяется после открытия; новая оплата автоматически не создаётся. |
| Неверный payer, recipient, сумма, reference, message, blockhash, сеть, статус или повторная подпись | Сервер не зачисляет платёж и не запускает сохранение. |
| Solana verified, Arweave недоступен | Оплата остаётся подтверждённой, тот же AR job/подписанные bytes повторно сверяются; новой SOL оплаты нет. |
| Промокод | Сохраняет существующий отдельный funded flow, envelope, head, историю и восстановление всех деревьев. |

Отдельно проверить реальное расширение Chrome на **devnet** после локальных тестов. Программная подпись и синтетический RPC ответ не доказывают работу Phantom/Solflare; подтверждение SOL не доказывает окончательное размещение в Arweave.
