# Независимое восстановление SEJIRE

Эта папка содержит автономный способ открыть **уже имеющийся зашифрованный
архив**. Для расшифровки нужны файл и его 12 слов SEJIRE. Сайт проекта, сервер,
Cloudflare, кошелёк, Solana, ArNS, npm и подключение к сети не нужны.
Используйте слова архива SEJIRE, а не фразу платёжного кошелька.

## Открыть в браузере без сети

Сохраните `recovery.html` на свой компьютер и откройте локальную копию в
современном браузере с WebCrypto. Выберите зашифрованный JSON или recovery kit,
введите слова и нажмите «Восстановить файл». Результат скачивается как обычный
**незашифрованный JSON**. Никакие данные или слова не отправляются в сеть;
страница не подключает CDN и содержит запрет сетевых соединений через CSP.
Она не запоминает слова в браузерном хранилище. После работы закройте страницу.

Если браузер не предоставляет WebCrypto для локального файла, используйте
командный инструмент ниже. Не вводите слова в произвольный сайт для обхода
этого ограничения. Сохранённая и проверенная копия инструмента позволяет
восстановление независимо от будущего владельца домена.

## Командный инструмент, Node 22+

`recover.mjs` — один самостоятельный файл со встроенным списком BIP39. Он
использует только встроенные возможности Node. Установка зависимостей не нужна.

```sh
node recover.mjs encrypted-archive-or-kit.json new-private-vault.json < private-sejire-words.txt
```

Файл слов создаёт сам владелец офлайн; на POSIX ему следует дать права `600`.
Слова не передаются в аргументах команды и не появляются в журнале инструмента.
Восстановленный файл создаётся с правами `600` на POSIX. Существующий файл не
перезаписывается. В Windows доступ определяется также настройками ACL.
Исходный зашифрованный файл не изменяется. При сбое записи новый выходной файл
может остаться неполным; исходник сохранён, а следующая попытка требует нового
имени выходного файла.

Обе версии принимают старый raw envelope `sejire/envelope/v1` и новый kit
`sejire/recovery-kit/v1`. Kit содержит исходный ciphertext, размер, digest и
необязательную квитанцию, **без слов и приватных ключей**. Квитанция без файла
не содержит семейных данных и не заменяет архив для офлайн-восстановления.

## Что сохранится в результате

Инструмент сохраняет точные аутентифицированные JSON-байты: все деревья,
родственные связи, поля и записанную историю. Он не выбирает «самую свежую»
версию, не объединяет архивы и не удаляет неизвестные поля. Как прочитать JSON
независимой программой, описано в `FORMAT.md`, раздел 4. Ссылки на отдельно
хранимые фото/медиа остаются ссылками; их байты не возникают из фразы.

Проверка AES-GCM подтверждает расшифровку, а digest kit — его связь с указанными
байтами. Это не проверка публикации в блокчейне и не обещание работы сети,
браузера, имени или компании через 200 лет. Экономическая модель хранения
Arweave и независимое чтение сохранённого файла — разные свойства.

## Состав переносимого набора

| Файл | Назначение |
| --- | --- |
| `recovery.html` | Автономная браузерная страница; вся логика и wordlist внутри |
| `recover.mjs` | Автономный Node 22+ decoder; вся логика и wordlist внутри |
| `FORMAT.md` | Точная derivation, шифрование, структура kit и plaintext |
| `envelope-v1.schema.json` | Схема существующего зашифрованного формата |
| `english.txt` | Канонический порядок 2 048 слов BIP39 для независимой реализации |
| `public-vectors.json` | Только публичные синтетические примеры и ожидаемые результаты |
| `LICENSES.txt` | Лицензии реализации и wordlist |

Публичные тестовые слова, ключевые производные и архивы из vectors известны
всем. Они не подходят для личных данных или кошельков и не должны получать
деньги. Настоящих фраз, ключей и семейных данных в наборе нет.

## Проверки разработчика

Из корня репозитория:

```sh
node --test tools/recovery/recovery.test.mjs
node --import ./apps/web/node_modules/tsx/dist/loader.mjs tools/recovery/interop.mts
node tools/recovery/build-html.mjs --check
sudo -H env PLAYWRIGHT_BROWSERS_PATH="$HOME/.cache/ms-playwright" SEJIRE_TEST_OS_OFFLINE=1 \
  unshare --net "$(command -v node)" --test tools/recovery/browser.test.mjs
```

Первая проверка работает без npm и сети; вторая сравнивает decoder с текущей
производственной криптографией приложения. Последняя проверка требует
проектный Playwright, все три установленных движка (Chromium, Firefox и WebKit)
и Linux с правом создать отдельное сетевое пространство имён. В примере выше
`PLAYWRIGHT_BROWSERS_PATH` указывает на cache пользователя, установившего браузеры;
при другом расположении нужно указать фактическую папку. Тест проверяет состояние
ядра: namespace отличается от `/proc/1`, есть только loopback, отсутствуют внешние
адреса и пригодные для передачи default routes IPv4/IPv6. Одной переменной
окружения для прохождения недостаточно. Kernel REJECT-записи IPv6 на loopback
разрешены: они отклоняют пакеты и не дают выхода в сеть.

Настоящая локальная копия HTML открывается через `file://`; HTTP дополнительно
запрещён и учитывается с момента создания контекста. Chromium и Firefox также
используют offline emulation и проверяют `navigator.onLine === false`. Основной
сценарий WebKit работает без этого флага в проверенной изолированной сети:
его эмуляция влияет на локальную загрузку. Короткая A/B-проба отдельно записывает
результаты `File.text()` и WebCrypto с флагом и без него на синтетических данных.
Чтение архивов, расшифровка и все шесть скачиваний каждого движка проходят без
сетевого доступа на уровне ОС. Новая диагностика состояния восстановления
и A/B-проб выводит движок, номер случая, безопасные сообщения интерфейса
и результаты API, без слов или plaintext.
Это Linux CI-проверка, а не проверка физического Safari/iOS; обычное использование
самого decoder не требует Linux или административных прав.
HTML воспроизводимо создаётся из
того же `recover.mjs` командой `node tools/recovery/build-html.mjs`.
Публичные vectors воспроизводятся только в разработке через
`node --import ./apps/web/node_modules/tsx/dist/loader.mjs tools/recovery/generate-public-vectors.mts`.
Это не реальные сохранения, платежи или публикации в Arweave.
